# V2.1 NOTES

> Historical artifact: code paths in this document refer to the v1/v2 layout. Current source is under `src/`, docs under `docs/`.

## What changed

### Must-fix

- **N1 registration PoP replay**: registration signatures are verified first, then
  `RegistrationChallengeStore.consume()` atomically re-checks challenge
  used/expiry/JKT/deviceNameHash and marks it used in one synchronous block.
  `/api/register` is rate-limited per IP and per canonical JKT, invalid proofs
  increment a challenge attempt counter (burned after five), and sessions are
  capped per device. Security tests fire 2 and 50 concurrent registrations with
  one challenge/proof over independent raw sockets; exactly one 200/session
  results, then a sequential replay is 403 `INVALID_REGISTRATION_CHALLENGE`.
- **Action-time presence**: for `presence:true` actions the presence token is
  validated at issuance but **not consumed**; `/api/action` requires it and
  consumes it inside the synchronous commit, bound to final action/view/
  scopeHash/bodyHash. Missing/reused/expired token → `PRESENCE_REQUIRED`;
  wrong scope/body → `PRESENCE_SCOPE_MISMATCH`.
- **Typed PresenceProvider seam**: `requestPresence()` may return `{code}` or
  `{assertion}`. The client sends `proof:{kind:"oob"|"webauthn", …}`. The server
  has an OOB verifier and a documented WebAuthn verifier contract; the demo
  WebAuthn path is a test-only fake under `ALLOW_TEST_HOOKS=1`, not production
  authentication.
- **Board ACL principal**: `boardMembers` is checked at issue and use. New demo
  users are seeded into `b1`/`b2`; a test-only membership hook removes membership
  to prove non-member issue denial and use-time continuity.
- **Chat capability writes**: `chat:join` / `chat:leave` are policy actions with
  `{chatId}` scope. Ambient `/api/chat/join|leave` routes were removed (404).
- **N6 draft re-hash**: `post:submit` re-reads the stored draft and recomputes
  `sha256(draft.text)`; it must match both the child scope and stored draft. A
  test-only mutation hook proves no publish after mutation.
- **N8 audit redaction**: non-admin audit masks `capId`, `deviceId`, `parentCap`,
  `resultId`, `scopeHash` and `bodyHash`. Admin token must be ≥32 chars and is
  compared via SHA-256 + `timingSafeEqual`. Audit and state reads are rate-limited.

### Also improved

- Rate limits for `/api/register`, `/api/state` and `/api/audit`.
- In-memory caps: sessions/device (10), devices (10,000), capabilities/device
  (1,000), drafts/device (50).
- `DEMO` server env (default on for the demo; `DEMO=0` disables) gates serving
  `/demo-hooks.js` and OOB console-code presence. `?demo=1` is only a UI instance
  switch, not a security boundary.
- OOB presence logs redact raw scope/body; they log only hashes and action/device.
- Demo `window.secrecy`/signing-oracle instance remains gated behind `?demo=1`.
- Docs now distinguish action-time presence, typed provider proof, board
  membership, masked audit, env demo gating, and known demo-only limitations.

## Remaining known issues / intentionally simplified

- WebAuthn is a contract + stub; only a test-only fake verifier exists. OOB console
  code remains a demo channel; same-page XSS can keylog it after typing.
- In-memory single-process store; `consumeCapability` is atomic only in-process.
  A DB conditional update/CAS is required across processes.
- HMAC capability envelopes are symmetric and process-local; the store is the
  authority.
- Bearer sessions in JS memory; no BFF/HttpOnly cookies, rotation, logout,
  CSRF/origin hardening, account model.
- No idempotency/receipt lookup after a lost response; no per-cap revoke; no
  clock skew/`nbf`.
- Audit is in-memory, capped, non-tamper-evident; admin token is a static env
  secret.
- Rate limits/caps are best-effort fixed windows/counters; per-device Sybil
  resistance is limited.
- No CSP (the lab injects a script); `DEMO=0` avoids serving the lab file but
  same-origin script capability remains if the demo file is deployed.
- App still uses `enterView`; `view()`/`can()` exist but are not used by the
  checked-in controllers.
- Sequence links remain client-memory; reload loses a pending submit link.
- Avatar remains metadata-only.
